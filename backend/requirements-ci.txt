# POURQUOI CE FICHIER EXISTE
#
# `pip install -r requirements.txt` ÉCHOUAIT sur les runners GitHub, et c'est la
# vraie raison des dix-sept jours de rouge : l'étape « Install backend
# dependencies » tombait, donc les tests ne s'exécutaient jamais — pas même les
# cinq fichiers qui étaient listés. Ce n'est pas que des tests échouaient : rien
# ne tournait.
#
# `requirements.txt` décrit l'environnement COMPLET du serveur de production :
# google-genai, litellm servi depuis un hôte privé, boto3, jq (qui compile
# libjq depuis les sources), fastuuid (qui compile du Rust)… Une centaine de
# paquets dont le backend n'importe AUCUN.
#
# Vérifié par analyse de l'arbre syntaxique de tout `backend/` : les seuls
# modules tiers réellement importés sont les dix-huit ci-dessous. Le reste est
# du poids que l'intégration continue n'a aucune raison de porter — et chaque
# paquet superflu est une façon de plus d'échouer.
#
# CE FICHIER NE REMPLACE PAS requirements.txt EN PRODUCTION. Il sert aux tests
# et au développement.
#
# Versions identiques à celles de requirements.txt partout où elles y figurent.
